# Times API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `/mosques.json` and `/times.json` to the Worker, serving mosque times from a daily KV copy and location times from Aladhan through the edge cache, without changing the Alexa flow.

**Architecture:** Pure helpers in small `src/*.js` modules (list parsing, query validation, timetable trimming, day building, refresh selection), unit-tested with Vitest in Node. `src/index.js` stays the entry point: `scheduled()` keeps the Alexa logic and adds a one-mosque-per-tick refresh, and `fetch()` routes the two new paths to `src/api.js`. KV binding `TIMES`. The Cache API is injected as a parameter so it can be faked in tests.

**Tech Stack:** Cloudflare Workers (ES modules, plain JavaScript), Workers KV, Cache API, Vitest (dev only), Wrangler.

**Spec:** `docs/superpowers/specs/2026-11-22-times-api-design.md`

## Global Constraints

- Free plan: 100,000 requests/day, 10 ms CPU per request, KV 100,000 reads/day and 1,000 writes/day.
- **No user request ever calls my-masjid.com or writes KV.**
- my-masjid is called about once a day per listed mosque, by the cron only.
- GUIDs, `VM_TOKEN`, `TEST_KEY` and Voice Monkey device IDs never appear in any `/mosques.json` or `/times.json` response.
- Alexa order is unchanged (in-memory, then direct my-masjid, then **new** KV fallback, then Aladhan). Jumu'ah replacement, `TUNE`, `?test=1` and the `/` text page are unchanged.
- `days` from 1 to 14, default 7. `method` default 15, `school` `0` or `1` with default 1. Coordinates rounded to 2 decimal places.
- Every time in `/times.json` is ISO 8601 with that date's UTC offset, for example `2026-11-22T06:02:00+00:00`.
- Response headers: `content-type: application/json`, `access-control-allow-origin: *`, `cache-control: public, max-age=3600`.
- Cache TTL = min(3600 s, seconds until the next midnight in the source's timezone).
- KV keys: `mosque:<id>` and `refresh-state`. A refresh retries after 1 hour on failure and runs again after 24 hours on success.

## Review Focus

- A BST or GMT change inside the requested days (e.g. 2027-03-28, 2026-10-25): each day carries its own offset (`+00:00` or `+01:00`). Test in Task 2.
- A Friday whose Jumu'ah list is empty or holds non-`HH:MM` strings: `jumuah` is `null`, not a crash or `"undefined"`. Test in Task 2.
- A my-masjid response where some day has an empty or malformed time: the refresh rejects it and keeps the old KV value. Test in Task 3.
- Malformed queries such as `lat=abc`, `lat=91`, both `masjid` and `lat` given, `days=0` or `days=15`: a `400` with a JSON error, never a `500`. Test in Task 1.
- A request on 28 December for 7 days: the January days are present and marked `estimated: true`, and 29 February falls back to 28 February. Test in Task 2.

### Task 2: Timetable trimming and day building

**Files:**
- Create: `src/timetable.js`, `src/days.js`, `test/timetable.test.js`, `test/days.test.js`, `test/fixtures/mymasjid-sample.json` (a hand-made minimal my-masjid response: `model.salahTimings` covering 25 Oct, 26 Oct, 28–31 Dec, 1–3 Jan and 28 Feb, plus `model.jumahSalahIqamahTimings`)

**Interfaces:**
- Produces:
  - `trimTimetable(json) -> {days: [{month, day, fajr, dhuhr, asr, maghrib, isha}], jumuah: string[]}`. It throws `Error("Bad timetable")` if `salahTimings` is empty, or if **any** day has a time that isn't `HH:MM`. It maps `zuhr` to `dhuhr`. `jumuah` holds only `HH:MM` strings, sorted. *(The Review Focus case lives here.)*
  - `todayInZone(tz: string, now: Date) -> {y, m, d}`
  - `addDays({y,m,d}, n) -> {y,m,d}`
  - `zonedIso({y,m,d}, "HH:MM", tz) -> "YYYY-MM-DDTHH:MM:00±HH:MM"`. Algorithm: take guess = `Date.UTC(y,m-1,d,h,mi)`, read the tz offset at guess with `Intl.DateTimeFormat(..., {timeZone: tz, timeZoneName: "longOffset"})` (where `"GMT"` means `+00:00`), set utc = guess − offset, read the offset again at utc, and use the second offset if it differs. Format the local wall time with that offset.
  - `buildMosqueDays(stored, tz, start: {y,m,d}, n) -> Day[]`, where `Day = {date, weekday, fajr, sunrise:null, dhuhr, asr, maghrib, isha, jumuah, estimated?}`. It matches by month and day. If there's no match for 29 Feb, it uses 28 Feb with `estimated:true`. Any day whose year is after `start.y` gets `estimated:true`. On a Friday `jumuah` = `zonedIso(stored.jumuah[0])` or `null`, and on other days it's `null`.
  - `secondsToMidnight(tz, now: Date) -> number`

- [ ] **Step 1: Write failing tests**
  - `trimTimetable(fixture).days[0]` has the keys `month, day, fajr, dhuhr, asr, maghrib, isha`. A fixture copy with one `isha: ""` throws `"Bad timetable"`. Jumu'ah `["13:30","x","13:00"]` becomes `["13:00","13:30"]`.
  - `zonedIso({y:2026,m:11,d:22},"06:02","Europe/London")` = `"2026-11-22T06:02:00+00:00"`. `zonedIso({y:2026,m:7,d:1},"13:00","Europe/London")` ends with `+01:00`.
  - `buildMosqueDays` from 2026-10-24 for 3 days: the 24th has `+01:00` and the 26th has `+00:00`.
  - From 2026-12-28 for 7 days: there are 7 days, the January ones have `estimated:true`, and the December ones have no `estimated` key.
  - A Friday with `jumuah: []` gives `jumuah: null`. 2026-11-27 (a Friday) with `["13:00"]` gives `"2026-11-27T13:00:00+00:00"`.
  - Start 2028-02-29 (when the stored data has no 29 Feb) uses the 28 Feb times and `estimated:true`.
  - `secondsToMidnight("Europe/London", new Date("2026-11-22T23:30:00Z"))` = 1800.
- [ ] **Step 2:** Run `npx vitest run test/timetable.test.js test/days.test.js`. Expected: FAIL.
- [ ] **Step 3:** Implement `src/timetable.js` and `src/days.js`.
- [ ] **Step 4:** Run `npm test`. Expected: PASS.

### Task 3: Daily refresh in the cron

**Files:**
- Create: `src/refresh.js`, `test/refresh.test.js`
- Modify: `src/index.js` (the `scheduled()` handler, and move the my-masjid URL into a shared `myMasjidUrl(guid)`), `wrangler.toml` (add `MOSQUES` to `[vars]` and a `[[kv_namespaces]]` binding `TIMES`, with the id filled in during Task 6)

**Interfaces:**
- Consumes: `parseMosques` (Task 1), `trimTimetable` (Task 2)
- Produces:
  - `pickNextToRefresh(mosques, state: {[id]: {ok: number|null, tried: number}}, nowMs) -> Mosque|null`. It returns the first mosque that has no state, or whose `ok` is older than 24 h **and** whose `tried` is older than 1 h. Otherwise it returns `null`.
  - `refreshOne(env, fetchFn, nowMs) -> Promise<{id, ok: boolean}|null>`. It reads `refresh-state`, picks a mosque, fetches `myMasjidUrl(guid)` with `fetchFn`, then calls `trimTimetable`. On success it writes `mosque:<id>` as `{fetchedAt, guid, name, timezone, days, jumuah}`, then writes `refresh-state`. On failure it logs the error, leaves `mosque:<id>` untouched, and writes `refresh-state` with only `tried` updated.
  - `myMasjidUrl(guid) -> string` (exported from `src/refresh.js`, and `src/index.js` imports it)

- [ ] **Step 1: Write failing tests** with an in-memory fake KV (`{get(k,"json"), put(k,v)}` backed by a `Map`) and a stubbed `fetchFn`:
  - With empty state it picks the first mosque.
  - When `ok` was 2 h ago it returns `null`.
  - When `ok` was 25 h ago and `tried` 2 h ago it picks that mosque.
  - When `ok` was 25 h ago and `tried` 10 min ago it returns `null`.
  - A successful `refreshOne` writes `mosque:duwt` with `days.length > 0` and `refresh-state.duwt.ok === now`.
  - A failing fetch (`status 500`) keeps the previous `mosque:duwt` value and sets only `tried`.
  - A fixture with a bad time keeps the previous value. *(This is the Review Focus case.)*
- [ ] **Step 2:** Run `npx vitest run test/refresh.test.js`. Expected: FAIL.
- [ ] **Step 3:** Implement `src/refresh.js`. In `scheduled()`, call `ctx.waitUntil(refreshOne(env, fetch, Date.now()).catch(e => console.log(...)))` **before** the existing Alexa logic, so a refresh failure can never stop the Alexa trigger. Skip it when `env.TIMES` is undefined.
- [ ] **Step 4:** Run `npm test`. Expected: PASS. Then run `npx wrangler deploy --dry-run`. Expected: it builds with no errors.
- [ ] **Step 5:** Commit: `git commit -m "Refresh one mosque per cron tick into KV"`
